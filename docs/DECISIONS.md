# Решения

## 001. Кумека и оркестратор — один проект

**Решение:** репозиторий называется `qmeka`, движок и UI живут вместе.

**Почему:** в коде приложение называет себя `Qmeka — thinking workspace` (`ui/app.py:23`),
столы лежат в `qmeka-projects\`, брендинг вставляется в страницы ревьюеров. Отдельного
проекта `qmeka` не существовало: имя появилось как продуктовая обёртка над движком
«orchestrator», а исходный цикл opencode ↔ z.ai остался внутри пресетом.

**Следствие:** восстанавливать надо одну вещь, а не две.

## 002. Статус paused, код не реанимируем целиком

**Решение:** репозиторий хранится как материал, приложение не запускается.

**Почему:** нет шести модулей (`zai_driver.py`, `cdp_ws.py`, `md2docx.py` и др.), `roles\`,
`prompts.json`; UI разъехался с исполнителем (дашборд ищет `plan.md`/`reply.md` в одной
раскладке, `fsm_v2` пишет в другой); драйверы завязаны на DOM z.ai.

**Следствие:** при возобновлении пишем ядро заново (~200 строк: контракт артефактов +
headless-вызов агента + таблица стадий + роль в промпте), а UI-кит и дизайн-документ берём отсюда.

## 003. Данные прогонов не в git

**Решение:** `qmeka-projects\`, `sessions\`, `out\`, `.venv\` — в `.gitignore`.

**Почему:** это состояние рабочей машины, а не исходники; в старом `.gitignore` было то же решение.
