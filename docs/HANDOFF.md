# Handoff: Qmeka

Обновлено: 2026-11-16.

## Где мы

Репозиторий собран из логов (см. `RECOVERY.md`), статус **paused**. Работа не продолжается,
пока не принято решение о возобновлении. Код не запускается: нет шести модулей и `roles\`.

## Что известно точно

- Qmeka и «оркестратор» — один проект. Оркестратор был движком (цикл opencode ↔ z.ai), Qmeka —
  именем и веб-UI, выросшими над ним. Исходный цикл остался пресетом «Simple Grill».
- Реализовано: DAG-канвас с портами, судья на 2–4 входа, пресеты и шаблоны, генерация пайплайна
  агентом по задаче, столы-проекты, Qmeka Chrome с визардом, окна стадий, метрики, backlog.
- Не реализовано: параметризация промптов по позиции в пайплайне (главная дыра ядра),
  нода инжекции, маскот, MCP-хаб, VPS-режим, сканирование скиллов.

## Следующие шаги, если возобновляем

1. **Восстановить дыры по смыслу.** `prompt_builder.py` и `roles\*.md` — самое ценное; писать
   заново по описанию ролей в `ORCHESTRATOR_DESIGN.md` и заметках воркспейса.
2. **Отвязать от DOM z.ai.** Драйверы браузерных сервисов — самая хрупкая часть; вместо
   кликов по селекторам — официальные API там, где они есть.
3. **Позиционная параметризация промптов** — то, без чего ядро неполно: инструкция должна
   зависеть от роли и от места стадии в графе.
4. **Метрика прогона.** Сейчас «получилось» определяет человек; нужен измеримый критерий,
   иначе цикл не сходится.
5. **Минимальный вертикальный срез:** запуск пайплайна из трёх стадий на одном вендоре,
   артефакты в файлах, без браузеров. Это проверяемо и переносимо.
