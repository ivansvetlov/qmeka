# Полный дизайн: Оркестратор z.ai ↔ opencode
*Консолидация: базовый + критика #1/#2 + гриль DeepSeek (отд. профиль, один чат, double-Enter, сценарии А/Б, раунды 4–5: ENTER_SEQ=2, фоллбэк technichka, webdriver-флаг, извлечение вердикта, T_stable_max, HUD/логи, матрица, метод CDP-ввода, лимиты чата, порядок гейтов, OS-фоллбэк) + **ГРИЛЬ GEMINI (Conditional Approval)**: динамический ENTER_SEQ по размеру, watchdog=done.json-первичен, анти-детект (капча-iframe + Bézier + бюджет контекста), clipboard save/restore, native-picker вместо drag-drop, FALLBACK_TECH в матрице. **Имплементация выполнена (см. §18): opencode — headless `opencode run` (§7); z.ai — CDP-драйвер; оркестратор `fsm.py` прошёл сквозной прогон N=1 (plan 14.3КБ → ревью z.ai).***

## 1. Цель и контекст
Автономный итеративный цикл улучшения дизайна/архитектуры с минимальным участием человека:
- **opencode** (агент на ПК) — старший архитектор, генерирует итерации. Драйвер — **только OS-автоматика** (TUI).
- **z.ai** (в отдельном профиле Chrome оркестратора, залогинен) — adversarial-ревьюер. Драйвер — **CDP первично, OS-фоллбэк**.
- **Оркестратор** — координирует, водит окна, перекладывает артефакты через файлы.

Платформа: Windows, ПК пользователя.

Перед paste — **сохранить/восстановить буфер обмена** (race-condition). Порог диалога уточняется в debug (§19). | Асимметрия | z.ai фокусируется на вопросах К opencode; opencode отвечает на каждый (мягкая петля). |
| Автономность | Без ожидания человека в цикле. |

## 2. Архитектура и поток данных
```
[Пользователь] --(Ctrl+Alt+Z, ввод задачи в оверлей)-->
   [Оркестратор]
      | 1) генерирует PROMPT_OPENCODE_START из prompts.json ({{USER_TASK}})
       | 2) впрыскивает в opencode (OS): paste(ПОЛНЫЙ промпт) → ENTER_SEQ (динамический)
      v
   [opencode] --пишет--> <SESSION>/01/plan.md + done.json + срезы + backlog_items
       | (watchdog: СНАЧАЛА done.json (авторитетный маркер) → ТОЛЬКО ПОСЛЕ него 10с стабилизация размера plan.md; вердикт НЕ нужен)
      v
   [Оркестратор] --z.ai (CDP/OS, тот же чат): attach allowlist из 01/*, PROMPT_ZAI-->
      v
   [z.ai] --ответ--> <SESSION>/02/reply.md (ВАЛИДАЦИЯ + извлечение ВЕРДИКТА для HUD)
      | (НЕ вставляется в opencode целиком; opencode читает файл)
      v
    [Оркестратор] --впрыскивает в opencode (OS): paste(ПОЛНЫЙ PROMPT_OPENCODE_CONT, с путями) → ENTER_SEQ (динамический)-->
      v
   [opencode] --читает 0<N>/reply.md + 0<P-2>/plan.md, отвечает на вопросы, пишет--> <SESSION>/03/...
```

## 3. Структура папок и файлов
`<WORKDIR>/<SESSION>/` (WORKDIR = `<repo>/sessions`, решено п.1; репозиторий: `C:\Workspace\projects\orchestrator`)
- `00/task.txt`, `00/start_prompt.md`, `00/continue_prompt.md` (каноничные промпты; впрыскивается их содержимое).
- `01/`,`03/`… (нечётные): `plan.md` + вложения + `session_slice_*.md` (≤5) + `0<N>/backlog_items.md` + `done.json {"role":"opencode","iter":N}`. (`done.json`/`backlog_items.md` — мета, НЕ аттачатся z.ai.)
- `02/`,`04/`… (чётные): `reply.md` (+ `log.json`).
- `zai_chat.txt` — URL чата z.ai (`/c/<uuid>`).
- `backlog.md` — агрегированный оркестратором в конце.
- `.lock` — singleton (PID).
- `journal.jsonl` — машинный лог.
- `run.log` — **человекочитаемый лог** (русские фразы, без кодов; хвост в HUD).
- `config.json` — пути, хоткеи, N, таймауты, CDP-порт, калибровка, `injection_mode`, `zai_upload_method`, `abs_paths_ok`.
- `prompts.json` — шаблоны промптов:
  ```json
  {
    "PROMPT_OPENCODE_START": "... {{USER_TASK}} ... {{SESSION}} ...",
    "PROMPT_OPENCODE_CONT": "... {{N}} ... {{SESSION}} ... {{PREV_PLAN}} ...",
    "PROMPT_ZAI": "... {{N}} ..."
  }
  ```

## 4. Старт (MVP, автоматический)
1. **Ctrl+Alt+Z** → singleton-проверка (`.lock` жив — HUD «уже запущен», выход; stale PID — удалить).
2. Оверлей ввода задачи → поля `USER_TASK` **и `N` (число итераций, БЕЗ значения по умолчанию — всегда спрашиваем, п.8)** → `00/task.txt` + генерация `00/start_prompt.md` из `prompts.json` (подстановка `{{USER_TASK}}`,`{{SESSION}}`).
3. Авто-калибровка opencode при запуске (утилита координат; первый раз — клик пользователя) → фокус поля → вставка полного промпта (с сохранением буфера обмена) → `ENTER_SEQ`.
4. opencode пишет `01/plan.md`+`done.json`, останавливается.
5. Watchdog: дожидается `done.json` (авторитетный маркер), затем 10с стабилизации размера `plan.md` в ожидаемой папке → цикл.

**UI opencode:** чистая сессия — центр; после обмена — низ. Локация — калибровкой.

## 5. Протокол цикла (FSM)
```
[LAUNCH] Ctrl+Alt+Z → overlay → save 00/task.txt + 00/start_prompt.md
  ▼ INJECT_START → focus opencode (OS) → paste(ПОЛНЫЙ PROMPT_OPENCODE_START, clipboard save/restore) → ENTER_SEQ (динамический)
  ▼ AWAIT_ARTIFACT(01)   [таймаут T_open=10-15мин, сброс при росте plan.md]
        СНАЧАЛА ждём появления done.json (он — единственный абсолютный триггер готовности).
        ТОЛЬКО ПОСЛЕ done.json — СТАБИЛИЗАЦИЯ размера plan.md:
        опрос размеров каждые ~2с; стабильно 10с → ок. Ограничено T_stable_max (default 120с,
        отдельный от T_open, отсчитывается ПОСЛЕ done.json); превышение → journal.warning + HUD-заметка
        + продолжение с текущими файлами (best-effort). дубль done.json → journal + берём первый.
        ДО появления done.json размер plan.md НЕ опрашивается (нет race-condition и пустой траты ресурсов).
  ▼ CHECKPOINT_1: stop_after_iter? → DUMP_BACKLOG → EXIT (показать launch-оверлей)
  ▼ OPEN_OR_REUSE_ZAI
        iter1: новый чат → save zai_chat.txt (URL /c/<uuid>)
        iter>1: navigate по URL; CDP-проверка, что тред загрузился (есть прошлые сообщения);
                если пуст/невалиден ИЛИ отправка отклонена (лимит сообщений/контекста) →
                НОВЫЙ чат + обновить zai_chat.txt + дописать в промпт «итерация N, история сброшена».
  ▼ COMPOSE (CDP: focus (Bézier-траектория мыши) + dispatchKeyEvent(PROMPT_ZAI) + setFileInputFiles(allowlist: plan.md + session_slice≤5 + ≤3 вложения)) → SEND
        [БЮДЖЕТ КОНТЕКСТА: сумма allowlist > ~100КБ → превентивно НОВЫЙ чат (сброс истории).
         верификация: сообщение появилось; retry; капча/попап/iframe[challenges] → ПЕРЕКЛЮЧЕНИЕ на OS-фоллбэк;
         отказ по лимиту сообщений/контекста → новый чат; **отказ прикрепления файлов** → каскад деградации (см. §6 «Отказ прикрепления»)]
  ▼ WAIT_STREAM_END [таймаут T_zai] стабильное отсутствие индикатора N сек + рост текста остановлен
  ▼ COPY_REPLY → SAVE 02/reply.md
        ВАЛИДАЦИЯ reply.md: не пустой + «ВЕРДИКТ»; если вердикт≠ready → «ВОПРОСЫ». retry≤2, потом journal+продолжить.
        ИЗВЛЕЧЕНИЕ ВЕРДИКТА (parser: ВЕРДИКТ → окно 200сим → ключевые слова готов/отклонить/правк;
        не найден/не распознан → needs_changes + journal + HUD) → для HUD.
  ▼ HUD по вердикту: «готов» → «Ревьюер: план готов — можно остановить (Ctrl+Alt+X)»;
        «отклонить» 2× подряд → немодальный алерт (цикл не блокируется; юзер сам Ctrl+Alt+X).
  ▼ CHECKPOINT_2: stop_after_iter? → DUMP_BACKLOG → EXIT (показать launch-оверлей)
  ▼ INJECT_POINTER → focus opencode (OS) → paste(ПОЛНЫЙ PROMPT_OPENCODE_CONT, с путями, clipboard save/restore) → ENTER_SEQ (динамический)
  ▼ CHECKPOINT_2b (после INJECT, до AWAIT): stop_after_iter? → DUMP_BACKLOG → EXIT
  ▼ AWAIT_ARTIFACT(03) [T_open + стабилизация]
  ▼ CHECKPOINT_1 → OPEN_OR_REUSE_ZAI (navigate same chat) → COMPOSE(attach 03/) → SEND → WAIT → COPY → 04/reply.md
  ▼ CHECKPOINT_2 → INJECT_POINTER → CHECKPOINT_2b → AWAIT_ARTIFACT(05) → …
  └─ пока iter < N
     ИЛИ Ctrl+Alt+X (stop_after_iter; срабатывает ТОЛЬКО в CHECKPOINT_1/2/2b)
     ИЛИ Ctrl+Alt+Shift+X (авария: DUMP_BACKLOG → EXIT в любой точке)
```
- `T_open` 10–15 мин; HUD: «opencode: 3 мин / таймаут: 12 мин» (обновление 1с; N=прошло, M=осталось).
- `DUMP_BACKLOG`: агрегирует `0<N>/backlog_items.md` → `backlog.md`.
- После EXIT — снова launch-оверлей.
- **Watchdog НЕ сканирует содержимое plan.md** (комплаенс/чтение — на z.ai). Вердикт извлекается из reply.md при его валидации.

## 6. Взаимодействие с z.ai
- **Профиль:** отдельный профиль оркестратора `chrome --remote-debugging-port=<P> --user-data-dir=C:\Orchestrator\ChromeProfile --disable-blink-features=AutomationControlled`. z.ai залогинен однократно (Setup), сессия сохраняется.
   - **Защита от детекта:** флаг `--disable-blink-features=AutomationControlled` сбрасывает `navigator.webdriver`, но современные защиты (Cloudflare/PerimeterX/Arkose) детектируют CDP по побочным признакам (`cdc_*` функции, аномальные тайминги `dispatchKeyEvent`, отсутствие реальных `mousemove`). Митигации: (1) перед фокусом поля — движение мыши по **Bézier-траектории** (кривая, не прямая); (2) человекоподобный темп: паузы 50–200 мс, редкие backspace-«ошибки»; (3) триггер OS-фоллбэка при появлении `iframe[src*="challenges"]` (капча), а не только при падении CDP. **Фаза 1:** проверить `Runtime.evaluate(() => navigator.webdriver)`; если `true` ИЛИ капча → ввод z.ai переводится на OS-автоматику. Stealth-плагины не используются.
   - **Драйвер:** CDP первично; **OS-фоллбэк** (pyautogui/win32) на окно Chrome z.ai при триггерах: (а) CDP-endpoint недоступен (Chrome не запущен/порт занят); (б) CDP не находит DOM-элементы (UI обновлён); (в) CDP-ввод не принимается; (г) **капча** `iframe[src*="challenges"]` появилась. При любом → авто-переключение + journal + HUD. Если и OS-фоллбэк не сработал → терминальный алерт + EXIT.
   - **Ввод текста (CDP):** подвести мышь к полю по Bézier-траектории (`mousemove` с кривой) → сфокусировать (`DOM.focus`/клик) → проверить фокус → `Input.dispatchKeyEvent` посимвольно/блоками с человекоподобными паузами. `Input.insertText` не используем (ненадёжно для contenteditable). Отправка — Enter или клик по кнопке. OS-фоллбэк: реальные клик+ввод+Enter.
- **Один чат на прогон:** iter1 — новый + save URL; iter>1 — navigate, verify; новый чат при сбое треда ИЛИ отказе по лимиту сообщений/контекста (всегда обновлять `zai_chat.txt` + дописать «итерация N, история сброшена — работай с вложением»). `PROMPT_ZAI` уже умеет работать без истории.
   - **Аттач:** CDP `setFileInputFiles` (plan.md + session_slice_*.md ≤5 + ≤3 вложения). `done.json`/`backlog_items.md` исключены. **Фаза-1:** инспекция DOM z.ai — стандартный `<input type=file>` или кнопка «скрепка». **OS-фоллбэк загрузки = НАТИВНЫЙ пикер, НЕ drag-drop** (drag-drop из Explorer в Chrome ненадёжен на Windows из-за UAC-конфликтов прав и геометрии зоны): клик по кнопке скрепки (координаты из калибровки Гейта 3) → ожидание ~500мс окна `#32770` (класс диалога Windows) → win32gui записать абс. путь в `Edit1` → `Enter`/`WM_COMMAND`. Детерминировано и не зависит от UAC.
   - **Отказ прикрепления (много файлов / большой вес):** проактивный лимит до отправки — `plan.md` + `session_slice_*.md` ≤5 + вложения ≤3, суммарно ≤~100КБ (превышение → `CTX_BUDGET`: новый чат и/или отбрасывание старейших slice/вложений). После `setFileInputFiles` — **верификация факта прикрепления** (DOM: чипы/счётчик файлов). Если z.ai вернул ошибку («файл слишком большой»/«макс. N файлов») ИЛИ число чипов ≠ ожидаемому — **каскад деградации**: (1) урезать до `plan.md` + 1 свежий slice, сбросить вложения, повторить; (2) ещё отказ и `plan.md` один слишком велик — **вставить текст `plan.md` прямо в тело сообщения** (поле ввода z.ai принимает большие вставки, в отличие от opencode), без файлов; (3) крайний случай — отправить `PROMPT_ZAI` без плана + `journal.warning` + HUD-алерт (деградация качества, но цикл не блокируется). OS-фоллбэк (нативный пикер) применяется при сбое CDP, но подчиняется тем же лимитам z.ai.
- **Конец стриминга:** CDP — отсутствие индикатора стабильно N сек + рост текста остановлен.
- **Верификация отправки:** после Enter — сообщение появилось; retry; капча/попап → алерт; отказ по лимиту → новый чат.
- **Копия ответа:** CDP — текст последнего ответа → `reply.md`.
- **Валидация reply.md:** не пустой + «ВЕРДИКТ»; если вердикт≠«готов» → «ВОПРОСЫ». retry≤2, потом journal+продолжить.
- **CDP-порт:** проверка доступности перед запуском; если занят — 9223/9224; порт в config; верификация личности Chrome (`/json/version`, user-data-dir).
   - **Setup (один раз):** оркестратор запускает изолированный профиль Chrome (порт 9222, флаг) и **сразу открывает URL чата z.ai** (из `zai_chat.txt`/config) → пользователь залогинивается вручную → оркестратор **сохраняет cookies (user-data-dir)** → **ТЕСТ ПЕРСИСТЕНТНОСТИ: закрывает и переоткрывает Chrome с тем же профилем, снова открывает z.ai и проверяет, что остался залогинен** (нет — алерт; см. §20 перенос куки). Attachment в чате поддерживается (подтверждено п.3).

## 7. Взаимодействие с opencode
- **Штатный драйвер (реализовано): headless `opencode run`.** Вместо инъекции в TUI
  используется детерминированный вызов:
  `opencode run "<msg>" --auto --format json --dir <SESSION>/0<N> --file <prompt.md>`.
  - Промпт кладётся в файл `prompt.md` и аттачится через `--file` (без shell-квотинга
    многострочного текста). Короткое `<msg>` = «Execute the task in the attached file
    prompt.md. Follow it exactly.»
  - Ответ агента извлекается из JSON-событий stdout (`{"type":"text","text":...}`),
    конкатенируется → пишется `plan.md` оркестратором. `done.json` оркестратор пишет
    сам (авторитетный маркер). Никакого TUI/фокуса/выбора сессии/ENTER_SEQ не требуется.
  - Преимущества: иммунен к краже фокуса, не зависит от состояния открытого TUI
    opencode, детерминирован, легко распараллеливается по итерациям.
- **Резервный драйвер (OS-автоматика, pyautogui/win32) — оставлен как фоллбэк** на случай,
  если headless `run` недоступен (нет CLI/сети). Тогда: калибровка точки ввода
  (`config.json.opencode_input_xy`, утилита в `debug_bootstrap.py --recalibrate`), фокус
  окна → клик поля → paste полного промпта (clipboard save/restore) → `ENTER_SEQ`
  (единый 2 Enter: диалог + пауза ~300мс + подтверждение), **Focus-guard (§21)** при краже
  фокуса. Этот путь НЕ прошёл валидацию вживую (промпт попадал в окно выбора сессии
  opencode, а не в поле агента), поэтому headless — основной.
- opencode читает `0<N>/reply.md` (ревью z.ai) и `0<P-2>/plan.md` (пред. план) по путям из
  промпта, пишет нечётную папку + `done.json` (последним), останавливается.

## 9. Порог 5 КБ (обход)
opencode показывает диалог подтверждения при большой вставке. `ENTER_SEQ` **единый** (промпты всегда >5КБ, п.2): `paste` (с сохранением буфера) → `Enter` (диалог) + пауза ~300мс + `Enter` (подтверждение). Ветвление по размеру убрано. technichka-фоллбэк не нужен, **кроме случая провала гейта 1 фазы 1** (возврат к инъекции голого пути для ВСЕХ впрысков; двойной провал → терминальный алерт+EXIT). z.ai получает материалы файлами. **Фаза-1 гейт 1:** вставить ~10 КБ, подтвердить приём без обрезки и корректность `ENTER_SEQ`.

## 10. Самодостаточность и экспорт сессии
z.ai не видит проект/чат. opencode выгружает `session_slice_*.md` (≤5) — фрагменты истории, diff'ы, выводы. Только текстовые файлы (.md/.txt/.json/.yaml).

## 11. Автономность, асимметрия и сценарии А/Б
- Цикл автономен.
- **Асимметрия:** opencode владеет проектом, но «слеп» к внешней оценке; z.ai видит только снимок → z.ai фокусируется на вопросах К opencode (помечает БЛОКИРУЮЩИЙ/УТОЧНЯЮЩИЙ), opencode отвечает на каждый (мягкая петля: если проигнорировал — z.ai пере-спрашивает и давит).
- **Сценарии (на z.ai, без жёстких гейтов оркестратора):**
  - **А:** opencode проигнорировал БЛОКИРУЮЩИЙ вопрос z.ai → z.ai в след. раунде пере-задаёт и указывает, что ответа не было.
  - **Б:** opencode написал КОД вместо плана → z.ai ловит как нарушение. Код в `plan.md` как **ИЛЛЮСТРАЦИЯ интерфейсов/контрактов** — допустим; код как **РЕАЛИЗАЦИЯ** (полные файлы, готовые к запуску) — нарушение.
- Оркестратор не проверяет содержимое/факт чтения файлов (watchdog = только наличие + стабилизация).

## 12. Бек-лог (вопросы к человеку)
- Если вопрос требует явного ответа человека и неразрешим автономно — opencode **НЕ блокируется**: решение по умолчанию (пометить «предположение») + **создать** `<SESSION>/0<N>/backlog_items.md` (если в ходе итерации появятся ещё — дописать).
- Оркестратор в конце агрегирует все `0<N>/backlog_items.md` → `backlog.md`, показывает пачкой.

## 14. Впрыск в opencode (полный промпт, `ENTER_SEQ`)
- **Старт:** содержимое `00/start_prompt.md` (после подстановки `{{USER_TASK}}`,`{{SESSION}}`).
- **Цикл (раунд N):** содержимое `00/continue_prompt.md` (после подстановки `{{N}}`,`{{SESSION}}`,`{{PREV_PLAN}}`).
- **`ENTER_SEQ` (единый, 2 Enter):** см. §7 — `paste` с clipboard save/restore → `Enter` (диалог) + ~300мс + `Enter`.
- **Фоллбэк `technichka` (режим из `config.json.injection_mode`, если гейт 1 провален):** `paste("<ABS>/00/start_prompt.md")` (или `continue_prompt.md`, путь <5КБ) → 1×Enter; применяется ко ВСЕМ впрыскам (START и CONT). Если и здесь opencode не выдал артефакт → терминальный алерт + EXIT.

| `VERDICT_READY` | Ревьюер: план готов | — |
| `VERDICT_NEEDS` | Ревьюер: нужны доработки | — |
| `VERDICT_REJECT` | Ревьюер: план отклонён | — |
| `FALLBACK_OS` | Переключились на резервный ввод | Основной способ не сработал, эмулируем клавиатуру |
| `FALLBACK_TECH` | Режим «Техничка» | Прямой ввод заблокирован, передаём команды через файлы конфигурации |

## 16. Декомпозиция на фазы
**Фаза 1 (Setup/Рекон) — обязательные гейты (порядок с зависимостями):**
1. **Setup предв.:** профиль Chrome + `--remote-debugging-port` + флаг `--disable-blink-features=AutomationControlled`; ручной логин z.ai.
2. **Гейт 2 — Калибровка opencode** (первый по зависимости): найти поле ввода (координаты/фокус). *Фоллбэк:* ручная калибровка каждый запуск.
3. **Гейт 4 + Гейт 1 вместе — прогон opencode:** отправить opencode промпт с абс. путём к тест-файлу + ~10 КБ. Проверить: (а) принял 10 КБ без обрезки и отправил через `ENTER_SEQ`; (б) прочитал файл по абс. пути (пробелы/Unicode). Если (а) не прошёл → `injection_mode="technichka"`.
4. **Гейт 3 — DOM z.ai** (независим, можно параллельно 2–3): инспекция механизма загрузки (кнопка «скрепка»/`input[type=file]`; координаты для OS-фоллбэка). *Фоллбэк загрузки:* **нативный пикер (#32770 через win32gui), НЕ drag-drop.**

Критерии/фоллбэки гейтов:
| Гейт | Успех | Фоллбэк |
|---|---|---|
| 1. 5КБ/ENTER_SEQ | ~10КБ принята, диалог подтверждён, без обрезки | `technichka` (<5КБ, голый путь) для ВСЕХ впрысков |
| 2. Калибровка | Координаты поля определены | Ручная калибровка каждый запуск |
| 3. DOM z.ai | Механизм загрузки определён | OS нативный пикер (#32770, win32gui) |
| 4. Абс. пути | opencode понимает путь с пробелами/Unicode | Относительные пути от workspace |

## 19. Debug-воркфлоу (эмпирическое определение параметров)
Включается флагом `debug` (показывается в HUD, п.9). Цель — автономно определить пороги, которые нельзя знать заранее, и дать пользователю тюнить таймауты/хуки по ходу userflow (п.10).

1. **Утилита координат (калибровка opencode, п.2/15/16):** при запуске — tkinter-окно с live `x,y` мыши; пользователь кликает в поле ввода opencode → координаты сохраняются в `config.json` и переиспользуются. opencode внутри WPS/TUI не требует детекции — только точка ввода.
2. **Порог диалога opencode (п.9):** скрипт в debug режиме прогрессивно вставляет в opencode блоки возрастающего размера (1→2→5→10→20 КБ) и фиксирует, при каком размере появляется диалог «все равно продолжить» → записывает `thresholds.paste_dialog_kb` в `config.json` + лог. (Штатно `ENTER_SEQ` = 2 Enter, т.к. промпты >порога.)
3. **Бюджет контекста z.ai (п.9):** накапливающе прикреплять файлы возрастающего веса, фиксировать отказ/забывание инструкций → `thresholds.zai_ctx_kb`. До определения — консервативный ~100 КБ.
4. **Тест персистентности логина z.ai (п.3/6):** после ручного логина — закрыть и переоткрыть Chrome с тем же `user-data-dir`, проверить, что z.ai остался залогинен; результат в лог + HUD.
5. **Логирование:** в debug — все события FSM, размеры файлов, координаты, ответы z.ai, тайминги пишутся в `run.log` подробно (человекочитаемо) параллельно `journal.jsonl`.
6. **Таймауты/хуки (п.10):** задаются в `config.json` и меняются пользователем в процессе; опционально — хуки событий (`on_iteration_start`, `on_zai_reply`, `on_error`) вместо жёстких таймаутов.

## 21. Устойчивость к краже фокуса и сторонним окнам
Во время автономного цикла могут всплывать чужие окна (напр. пустое cmd от планировщика/крона), которые перехватывают фокус и уводят ввод не туда. Обработка:

- **z.ai (CDP) иммунен:** `Input.dispatchKeyEvent` / `setFileInputFiles` идут в страницу через DevTools, OS-фокус не нужен. Уязвим только OS-фоллбэк z.ai (там — те же focus-guard-ы, что для opencode).
- **opencode (OS-ввод) — focus-guard:**
  1. Перед каждой вставкой/серией клавиш проверить, что foreground-окно == цель (по координате `opencode_input_xy` из config / заголовку / pid).
  2. Если нет — вернуть фокус: `SetForegroundWindow` + `AttachThreadInput` (обход ограничения Windows «нельзя поднять окно чужого процесса»), пауза на оседание, повторная проверка.
  3. Если фокус украден **во время** ввода — прервать серию, перефокусировать, **повторить ВСЮ `ENTER_SEQ`** (не докидывать символы в чужое окно).
  4. После N неудач — **HUD-алерт** (человек в контуре), не тихий баг.
- **Бенign popups (крон/планировщик):** опциональный whitelist по заголовку/команде — переподнимать цель поверх либо (если мешает) прибивать по известному имени. Ядро устойчивости — focus-guard + retry, перекрывает большинство случаев без спец-логики.

## 20. Аутентификация z.ai: детект разлогина и перенос куки
Автономность упирается в сохранность сессии Google/z.ai между прогонами и во время долгого цикла.

- **Детект разлогина (в z.ai-драйвере, Фаза 4–5):** перед каждым шагом z.ai проверять состояние страницы (наличие формы логина / отсутствие DOM чата / редирект на account.google). При разлогине — **HUD-алерт (человек в контуре)** + пауза, НЕ молчаливый сбой. Переход на новый чат при сбое треда не решает проблему разлогина — требуется ручной вход.
- **Перенос куки из основного Chrome (быстрый старт / восстановление):** `debug_bootstrap.py --clone-from "<путь к профилю основного Chrome>"` копирует файл `Cookies` (и `Network/Cookies`) в оркестраторский `user-data-dir`. **Условие:** основной Chrome должен быть ЗАКРЫТ (файл заблокирован). DPAPI-шифрование куки — на уровне Windows-пользователя, поэтому на той же машине/юзере куки расшифровываются и работают. После клонирования — автопроверка «залогинен ли z.ai».
- **Резервное сохранение/восстановление куки (позднее):** экспорт куки из оркестраторского профиля в файл после успешного логина и реимпорт при старте (CDP `Network.setCookies` или копия файла) — чтобы не логиниться вручную каждый прогон.
- **Частые причины выкидывания:** 2FA/подтверждение устройства на аккаунте Google (блокирует автоперелогин — отключить для этого аккаунта), сессионные cookie, не сброшенные на диск при жёстком убийстве Chrome (использовать корректное закрытие), строгие настройки Chrome («удалять куки при выходе»).
- **Рекалибровка координат opencode** без полного прогона: `debug_bootstrap.py --recalibrate` (несколько кликов → берётся самая нижняя точка ввода).
